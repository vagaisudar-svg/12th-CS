12.1

Introduction to SQL

What SQL is, and where it came from.

A. What is it?

Textbook definition
The Structured Query Language (SQL) is a standard programming language to access and manipulate databases. SQL allows the user to create, retrieve, alter, and transfer information among databases. It is a language designed for managing and accessing data in a Relational Data Base Management System (RDBMS).

SQL என்பது தரவுத்தளங்களை (databases) அணுகவும் கையாளவும் பயன்படும் ஒரு நிலையான நிரலாக்க மொழி. இதைக் கொண்டு நாம் தரவுகளை உருவாக்கலாம் (create), பெறலாம் (retrieve), மாற்றலாம் (alter), மற்றும் இடமாற்றம் செய்யலாம் (transfer). இது Relational Database Management System (RDBMS) -ல் தரவுகளை நிர்வகிக்கவும், அணுகவும் உருவாக்கப்பட்ட மொழி.

B. Real-life analogy Easy Explanation

Think of a database as a large steel cupboard full of labelled folders (tables). SQL is the set of instructions you give a librarian: "open this folder", "add this new sheet", "cross out this row", "show me only the sheets where age is above 18". You never touch the folders yourself — you just speak SQL, and the database does the work.

ஒரு database-ஐ பல கோப்புகள் (tables) அடங்கிய அலமாரி என்று நினைத்துக் கொள்ளுங்கள். SQL என்பது நீங்கள் ஒரு நூலகருக்குக் கொடுக்கும் அறிவுறுத்தல்கள் போன்றது — "இந்தக் கோப்பைத் திற", "இந்தப் புதிய தகவலைச் சேர்", "இந்த வரிசையை நீக்கு" என. நீங்கள் நேரடியாகத் தொடாமல், SQL மொழியில் கேட்டவுடன் database அதைச் செய்யும்.

C. A short history Textbook

There are many versions of SQL. The original version was developed at IBM's Research centre and was originally called Sequel in the early 1970s. Later the name was changed to SQL. In 1986, ANSI (American National Standard Institute) published an SQL standard, updated again in 1992. The latest SQL standard was released in 2008 and named SQL 2008.

NOTE (TEXTBOOK)Latest SQL standard as of now is SQL 2008, released in 2008.

SQL-ன் முதல் பதிப்பு IBM ஆய்வு மையத்தில் 1970-களின் தொடக்கத்தில் உருவாக்கப்பட்டது, அப்போது அதன் பெயர் Sequel. பின்னர் அதன் பெயர் SQL ஆக மாற்றப்பட்டது. 1986-ல் ANSI SQL தரநிலையை வெளியிட்டது, 1992-ல் மீண்டும் புதுப்பிக்கப்பட்டது. சமீபத்திய தரநிலை SQL 2008.

12.2

Role of SQL in RDBMS

Databases, tables, fields and records — the vocabulary everything else is built on.

A. What is it?

Textbook RDBMS stands for Relational DataBase Management System. Oracle, MySQL, MS SQL Server, IBM DB2 and Microsoft Access are RDBMS packages. SQL is the language used to access data in such databases.

In general, a Database is a collection of tables that store sets of data that can be queried for use in other applications. RDBMS is a type of DBMS with a row-based table structure that connects related data elements and includes functions related to Create, Read, Update and Delete operations — collectively known as CRUD.

The data in RDBMS is stored in database objects called Tables. A table is a collection of related data entries and consists of rows and columns.

Field (column)

A field is a column in a table designed to maintain specific related information about every record in the table. It is a vertical entity — e.g. AdmnNo, StudName, StudAge in a student table.

Record (row)

A Record is a row — a collection of related fields that exist in a table. It is a horizontal entity representing the details of one particular student.

The column Name (running down the whole table) is a field. The single highlighted row above — everything about Ashish — is one record.

Did you know? Textbook

SQL is a language used for accessing databases, while MySQL is a database management system — like SQL Server, Oracle, Informix, Postgres, etc. MySQL is an RDBMS.

12.3

Processing Skills of SQL

Seven things SQL can do for a database, in the textbook's own words.

Textbook — verbatim list
  1. Data Definition Language (DDL): provides commands for defining relation schemas (structure), deleting relations, creating indexes and modifying relation schemas.
  2. Data Manipulation Language (DML): includes commands to insert, delete, and modify tuples in the database.
  3. Embedded Data Manipulation Language: the embedded form of SQL used in high level programming languages.
  4. View Definition: SQL also includes commands for defining views of tables.
  5. Authorization: commands for access rights to relations and views of tables.
  6. Integrity: SQL provides forms for integrity checking using condition.
  7. Transaction control: commands for file transactions and control over transaction processing.

Easy Explanation

Of these seven, this chapter focuses on the four you will actually type: DDL (build the table), DML (fill it with data), DQL (ask it questions), and TCL (save or undo your changes). Keep this list in mind — every command you meet from here belongs to one of these families.

12.5

The Five Components of SQL

Every SQL command you will ever type belongs to one of these five families.

DDL — Data Definition Language

Defines the database structure or schema. Creates and modifies the structure of database objects.

CommandFunction
CREATETo create tables in the database.
ALTERAlters the structure of the database.
DROPDelete tables from database.
TRUNCATERemove all records from a table, also release the space occupied.

DML — Data Manipulation Language

Used for adding, removing, and modifying data — but not the table's schema.

CommandFunction
INSERTInserts data into a table.
UPDATEUpdates existing data within a table.
DELETEDeletes records from a table, but not the space occupied.

Two types: Procedural DML — user specifies what data is needed and how to get it. Non-Procedural DML — user specifies only what data is needed.

DCL — Data Control Language

Controls access to data stored in a database (authorization).

CommandFunction
GRANTGrants permission to perform specific tasks.
REVOKEWithdraws access permission given by GRANT.

TCL — Transactional Control Language

Manages changes made to data in a table by DML statements.

CommandFunction
COMMITSaves any transaction into the database permanently.
ROLLBACKRestores the database to the last commit state.
SAVEPOINTTemporarily saves a transaction, so you can rollback.

DQL — Data Query Language

Commands used to query or retrieve data from a database.

CommandFunction
SELECTDisplays the records from the table.

Vocabulary 12.7 Textbook

TermMeaning
KeywordsThey have a special meaning in SQL. They are understood as instructions.
CommandsInstructions given by the user to the database, also known as statements.
ClausesBegin with a keyword and consist of a keyword and an argument.
ArgumentsThe values given to make the clause complete.

12.6

Data Types

Every field must be told what kind of value it will hold.

Textbook The data in a database is stored based on the kind of value stored in it — this is the data type of the field. All the values in a given field must be of the same type. The ANSI SQL standard officially recognises only Text and Number data types, while commercial programs add types like Date and Time.

Data TypeDescription
char (Character)Fixed width string value, enclosed in single quotes. E.g. Anu's is written 'Anu' 's'.
varcharVariable width character string — similar to char except size varies considerably.
dec (Decimal)A fractional number e.g. 15.12. Size has two parts: precision (total digits) and scale (digits right of the decimal point). Scale cannot exceed precision.
numericSame as decimal, except the maximum number of digits may not exceed the precision argument.
int (Integer)A number without a decimal point. No size argument is used.
smallintSame as integer, but the default size may be smaller than Integer.
floatA floating point number in base-10 exponential notation, precision up to 64.
realSame as float, but no size argument; precision up to 64.
doubleSame as real, except the precision may exceed 64.

Common mistake

Forgetting the quotes around char/varchar values is a classic beginner slip: 'Chennai' is correct, Chennai without quotes will cause an error. Numbers (int, dec, float...) never take quotes.

12.7.1 · DDL Commands

CREATE TABLE

Building the structure a table's data will live in.

Syntax Textbook 
CREATE TABLE <table-name>
(<column name> <data type> [<size>]
 <column name> <data type> [<size>] ……
);

When a table is created, its columns are named, and data types and sizes are specified. Each table must have at least one column.

Textbook example

Creating the Student table

CREATE TABLE Student
(Admno   integer,
 Name    char(20),
 Gender  char(1),
 Age     integer,
 Place   char(10),
);

This is a simple table structure without any restrictions — every field can be left empty, and duplicate values are allowed anywhere.

How this executes — step by step Easy Explanation

  1. SQL reads the table name: Student.
  2. It reads each column definition in order, left to right: name, type, optional size.
  3. An empty table with five labelled, typed columns is created — no rows yet.
  4. You now use INSERT to start adding records.

12.7.2

Type of Constraints

Rules that stop bad data from ever entering a table.

Textbook Constraints are used to limit the type of data that can go into a table. This ensures the accuracy and reliability of the data in the database. Constraints ensure database integrity, therefore they are also known as database integrity constraints. They can be a Column constraint (applies to one column only) or a Table constraint (applies to a group of one or more columns).

NOT NULL — a field must always contain a value 
CREATE TABLE Student
(
Admno integer NOT NULL PRIMARY KEY,  -- Primary Key constraint
Name  char(20) NOT NULL,
Gender char(1),
Age   integer,
Place char(10),
);

Admno (integer) and Name (char) are both defined NOT NULL — these two fields must always have a value. Gender, Age and Place have no constraints.

UNIQUE — no two rows may repeat this value 
CREATE TABLE Student
(
Admno integer NOT NULL UNIQUE,  -- Unique constraint
Name  char(20) NOT NULL,
Gender char(1),
Age   integer,
Place char(10),
);

The UNIQUE constraint ensures no two rows share the same value in that column. It can only be applied to fields already declared NOT NULL. Applying two constraints to one field like this — NOT NULL UNIQUE — is called a multiple constraint: the constraints are separated by a space, with a comma at the end of the field definition.

PRIMARY KEY — uniquely identifies a record 
CREATE TABLE Student
(
Admno integer PRIMARY KEY,  -- Primary Key constraint
Name  char(20) NOT NULL,
Gender char(1),
Age   integer,
Place char(10),
);

Similar to UNIQUE, except only one field of a table can be set as primary key, and a primary key does not allow NULL values either.

DEFAULT — fills in a value automatically 
CREATE TABLE Student
(
Admno integer PRIMARY KEY,
Name  char(20) NOT NULL,
Gender char(1),
Age   integer DEFAULT 17,  -- Default Constraint
Place char(10)
);

When no value is given for Age, it is automatically set to 17.

CHECK — restricts values to a condition 
CREATE TABLE Student
(
Admno integer PRIMARY KEY
Name  char(20) NOT NULL,
Gender char(1),
Age   integer CHECK (Age <=19),  -- Check Constraint
Place char(10),
);

Only ages of 19 or below are accepted. The check constraint may use relational and logical operators in its condition.

Table constraint — a constraint spanning several columns 
CREATE TABLE Student1
(
Admno integer NOT NULL,
Firstname char(20),
Lastname  char(20),
Gender char(1),
Age   integer,
Place char(10),
PRIMARY KEY (Firstname, Lastname)  -- Table constraint
);

Here Firstname and Lastname together form the primary key — this is a Table constraint, normally written at the end of the definition.

Common mistakes

  • ❌ Using UNIQUE on a field that isn't NOT NULL — many systems require NOT NULL first.
  • ❌ Trying to set two fields as PRIMARY KEY individually — only one column-level primary key is allowed (use a table constraint for a composite key).
  • ❌ Forgetting that PRIMARY KEY already disallows NULLs — you don't need to add NOT NULL separately.
Quick check: Which constraint would you use so that every student's Admno is automatically unique AND used to identify each record?
12.7.3 · DML Commands

INSERT · DELETE · UPDATE

Once the structure exists, these three commands manage the data inside it.

INSERT — add a new record 
INSERT INTO <table-name> [column-list] VALUES (values);

INSERT INTO Student (Admno, Name, Gender, Age, Place)
VALUES (100, 'Ashish', 'M', 17, 'Chennai');

The order of values must match the order of columns named. Specifying column names is optional if you supply data for every column, in schema order:

INSERT INTO Student VALUES (102, 'Akshith', 'M', 17, 'Bangalore');

You can also insert into only some columns:

INSERT INTO Student (Admno, Name, Place) VALUES (103, 'Ayush', 'Delhi');
DO YOU KNOWIn the INSERT command, fields that are omitted will take either their DEFAULT value (if one is defined) or NULL.
DELETE — permanently remove records 
DELETE FROM table-name WHERE condition;

-- Delete one record
DELETE FROM Student WHERE Admno=104;

-- Delete every record (table stays, but becomes empty)
DELETE FROM Student;

DELETE removes the entire row, never individual fields — no field argument is needed. It does not free the disk space the table occupies (TRUNCATE and DROP handle that, coming up next).

UPDATE — change existing values 
UPDATE <table-name> SET column-name = value, column-name = value, …
WHERE condition;

UPDATE Student SET Age = 20 WHERE Place = 'Bangalore';

-- Update multiple fields at once
UPDATE Student SET Age=18, Place = 'Chennai' WHERE Admno = 102;

The WHERE clause chooses which rows change; SET says what changes. Leave out WHERE and every row is updated — a very common beginner mistake.

Common mistake — the missing WHERE

❌ UPDATE Student SET Age = 20; — this quietly sets every student's age to 20, because there is no WHERE clause to restrict it. Always double-check your WHERE condition before running UPDATE or DELETE.

12.7.4 · Additional DDL Commands

ALTER · TRUNCATE · DROP

Changing — or removing — a table you've already built.

ALTER — change the table's structure 
-- Add a column
ALTER TABLE <table-name> ADD <column-name> <data type> <size>;
ALTER TABLE Student ADD Address char;

-- Modify a column's type/size
ALTER TABLE <table-name> MODIFY <column-name> <data type> <size>;
ALTER TABLE Student MODIFY Address char (25);

-- Rename a column
ALTER TABLE <table-name> CHANGE old-column-name new-column-name new column definition;
ALTER TABLE Student CHANGE Address City char(20);

-- Remove a column
ALTER TABLE <table-name> DROP COLUMN <column-name>;
ALTER TABLE Student DROP COLUMN City;

DELETE vs TRUNCATE vs DROP Textbook comparison

CommandWhat happens
DELETEDeletes only the rows matching the WHERE clause (or all rows if none given). Does not free the space occupied by the table.
TRUNCATEDeletes all the rows; the table structure remains, and the space is freed.
DROPRemoves the object entirely from the database — all rows deleted and the table structure itself is removed. Once dropped, a table cannot be recovered.
TRUNCATE TABLE Student;
DROP TABLE Student;

12.7.5 · DQL Command

SELECT — retrieving data

The single most-used command in SQL.

Syntax 
SELECT <column-list> FROM <table-name>;

table-name is where the information comes from. column-list is one or more columns you want to see.

SELECT Admno, Name FROM Student;

-- every column, every row
SELECT * FROM Student;
DISTINCT — remove duplicate rows 
SELECT DISTINCT Place FROM Student;

Eliminates redundant repeated values so each place appears only once. When DISTINCT is used, only one NULL value is returned even if several NULLs occur.

ALL — keep every duplicate 
SELECT ALL Place FROM Student;

The opposite of DISTINCT — every row's value is shown, duplicates included.

12.7.5.2 – 12.7.5.4

WHERE, BETWEEN, IN & NULL

Filtering rows down to exactly what you need.

WHERE clause 
SELECT <column-name>[,<column-name>,….] FROM <table-name> WHERE <condition>;

SELECT Admno, Name, Place FROM Student WHERE Place = 'Chennai';
SELECT Admno, Name, Age FROM Student WHERE Age >= 18;

Relational operators = < <= > >= <> compare values. Logical operators OR, AND, NOT combine multiple conditions:

SELECT Admno, Name, Age, Place FROM Student
WHERE (Age>=18 AND Place = 'Delhi');

SELECT Admno, Name, Age, Place FROM Student
WHERE (Age>=18 OR Place ='Delhi');

SELECT Admno, Name, Place FROM Student WHERE (NOT Place ='Delhi');
BETWEEN and NOT BETWEEN

Defines a range of values a record must fall into (inclusive of both ends).

SELECT Admno, Name, Age, Gender FROM Student
WHERE Age BETWEEN 18 AND 19;

SELECT Admno, Name, Age FROM Student
WHERE Age NOT BETWEEN 18 AND 19;
IN and NOT IN

IN specifies a list of values to match — similar to a chain of OR conditions.

SELECT Admno, Name, Place FROM Student
WHERE Place IN ('Chennai', 'Delhi');

SELECT Admno, Name, Place FROM Student
WHERE Place NOT IN ('Chennai', 'Delhi');
NULL values 
SELECT * FROM Student WHERE Age IS NULL;
NOTENon-NULL values in a table can be listed using IS NOT NULL.

12.7.5.5 – 12.7.5.8

ORDER BY · GROUP BY · HAVING

Sorting rows, and summarising them into groups.

ORDER BY — sort the results 
SELECT <column-name>[,<column-name>,….] FROM <table-name>
ORDER BY <column1>,<column2>,… ASC | DESC;

SELECT * FROM Student ORDER BY Name;
SELECT * FROM Student WHERE Age>=18 ORDER BY Name DESC;
  1. By default, ORDER BY sorts in ascending order.
  2. Use DESC for descending, ASC to be explicit about ascending.
NOTEThe ORDER BY clause does not affect the original table. Sorting can be done on multiple fields.
GROUP BY — group rows with identical values 
SELECT <column-names> FROM <table-name> GROUP BY <column-name> [HAVING condition];

SELECT Gender, count(*) FROM Student GROUP BY Gender;

GROUP BY is mostly used together with aggregate functions (like count(*)) to produce summary reports — for example, counting how many male and female students there are.

NOTEThe * is used with COUNT to include NULL values too.
HAVING — filter the groups themselves 
SELECT Place, count(*) FROM Student GROUP BY Place HAVING place = 'Chennai';

WHERE filters individual rows before grouping; HAVING filters the groups after they are formed — and can include aggregate functions like COUNT.

12.7.6 · TCL Commands

COMMIT · ROLLBACK · SAVEPOINT

Undo-and-redo for your database changes.

COMMIT 
COMMIT;

Permanently saves any transaction to the database. Changes made by INSERT, UPDATE, DELETE are not permanent until COMMIT is given — and once COMMIT runs, those changes can no longer be rolled back.

SAVEPOINT 
SAVEPOINT savepoint_name;

Temporarily saves the current state of the table under a name, so you can jump back to it later, even without a full COMMIT.

ROLLBACK 
ROLL BACK TO save_point_name;

Restores the database to the last committed state, or to a named SAVEPOINT.

Textbook walk-through

Watch a transaction unfold

INSERT INTO Student VALUES (107, 'Beena', 'F', 20, 'Cochin');
COMMIT;
-- Beena is now permanent.

UPDATE Student SET Name = 'Mini' WHERE Admno=105;
SAVEPOINT A;
-- Revathi is renamed Mini, and this moment is bookmarked as "A".

INSERT INTO Student VALUES (108, 'Jisha', 'F', 19, 'Delhi');
SAVEPOINT B;
-- Jisha is added, bookmarked as "B".

ROLLBACK TO A;
-- Jisha disappears again — the table returns exactly to how it
-- looked right after savepoint A (Mini is still there, Beena stays).

Error Detector

Common beginner mistakes with this chapter's syntax — spot the fix.

❌ Incorrect

INSERT INTO Student VALUES (105, Revathi, 'F', 19, 'Chennai');

What's wrong? Revathi is a char value and must be inside quotes. This is a Syntax error — the database cannot even understand the command.

✅ Correct

INSERT INTO Student VALUES (105, 'Revathi', 'F', 19, 'Chennai');

❌ Incorrect

UPDATE Student SET Age = 20;

What's wrong? No WHERE clause — every single row gets Age changed to 20. This runs without any error message, so it is a Logical error: the command is syntactically fine but does not do what was intended.

✅ Correct

UPDATE Student SET Age = 20 WHERE Place = 'Bangalore';

❌ Incorrect

SELECT Admno, Name FROM Student WHERE Age BETWEEN 19 AND 18;

What's wrong? The lower value must come first. BETWEEN 19 AND 18 describes an impossible range, so the query silently returns zero rows — another Logical error.

✅ Correct

SELECT Admno, Name FROM Student WHERE Age BETWEEN 18 AND 19;

❌ Incorrect

CREATE TABLE Student
(Admno integer PRIMARY KEY
 Name char(20) NOT NULL,
 ...);

What's wrong? A comma is missing after PRIMARY KEY — every column definition except the last needs a comma to separate it from the next. This is a Syntax error.

✅ Correct

CREATE TABLE Student
(Admno integer PRIMARY KEY,
 Name char(20) NOT NULL,
 ...);

Exam Prep

Exam Revision

Everything the chapter wants you to walk out remembering.

Must Know

  • SQL is a language that helps to create and operate relational databases.
  • MySQL is a database management system.
  • The five components of SQL: DDL, DML, DQL, TCL, DCL.
  • DDL provides statements for creation and deletion of tables.
  • DML provides statements to insert, update and delete data of a table.
  • DCL provides authorization commands to access data.
  • TCL commands manage transactions in a database.
  • DQL commands generate queries in a database.
  • The CREATE TABLE command creates a new table.

Must Remember — key syntax

CREATE TABLE table-name (column datatype [size], … );
INSERT INTO table-name [(cols)] VALUES (values);
DELETE FROM table-name [WHERE condition];
UPDATE table-name SET col=value, … WHERE condition;
ALTER TABLE table-name ADD | MODIFY | CHANGE | DROP COLUMN …;
TRUNCATE TABLE table-name;
DROP TABLE table-name;
SELECT [DISTINCT|ALL] cols FROM table-name
  [WHERE condition]
  [GROUP BY col [HAVING condition]]
  [ORDER BY col [ASC|DESC]];
COMMIT; / SAVEPOINT name; / ROLLBACK TO name;

One-Minute Revision

DDL builds structure (CREATE, ALTER, DROP, TRUNCATE). DML fills it (INSERT, UPDATE, DELETE). DQL reads it (SELECT, with DISTINCT/WHERE/BETWEEN/IN/ORDER BY/GROUP BY/HAVING). DCL controls who can touch it (GRANT, REVOKE). TCL protects it (COMMIT, ROLLBACK, SAVEPOINT). Constraints — NOT NULL, UNIQUE, PRIMARY KEY, DEFAULT, CHECK — keep the data itself honest.

Important programs to remember

Be ready to write, from memory: a CREATE TABLE with at least one constraint, an INSERT with a partial column list, an UPDATE with SET + WHERE, and a SELECT combining WHERE with ORDER BY. These four appear, in some form, in nearly every exam.
